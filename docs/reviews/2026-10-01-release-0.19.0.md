# 0.19.0 Windows release verification

Code Start can now open a project in VS Code, and keys whose session reports no
activity show that it is open instead of turning grey.

- `Open with` adds **VS Code**. A press starts `Code.exe <folder>` directly (no
  shell, cwd set to the folder), then asks the Claude Code extension to show its
  panel through `--open-url vscode://anthropic.claude-code/open`. A folder VS Code
  already has open is focused rather than opened twice. A Companion running for
  the same folder is left alone.
- A VS Code key shows the project name and `VS Code` while a VS Code window's
  title names the folder, and for 15 seconds after a press. One shared
  PowerShell watcher lists window titles every 3 seconds and stops when no key
  asks for it.
- Terminal and VS Code modes cannot tell when Claude waits for input. They now
  draw in the running green with no blink and no sweep; grey stays reserved for
  `Closed`.
- package.json regained the `scripts` and `devDependencies` the 0.18.4 commit
  dropped by accident, without which `npm run release:windows` cannot run.

## Review

An independent code review found no critical or high issues. Fixed before
release: the VS Code cwd (a cold-started VS Code would otherwise hold the plugin
folder and block updates); `-EncodedCommand` replaced with a plain `-Command`
for the watcher; restart of a silent watcher; a second `error` event crashing
the plugin; case-insensitive folder matching; the key briefly dropping to
`Closed` after a press; and a failed panel request failing the whole launch.

Known limits: the window match uses the folder name, so two open folders with
the same name both light the key, and a custom `window.title` hides it. On a
very slow cold start the panel request can reach another VS Code window.
